## Технические решения

| Решение | Почему | Заход |
|---|---|---|
| Каждая версия фото — под своим ключом (`catalog/<товар>/<uuid>.webp`), старые файлы удаляются только после записи в базе через очередь с повторами | замена фото никогда не ломает живую страницу, а сбой не оставляет «мёртвых» ссылок | 1, 2, 11 |
| Фото сайта — через оптимизатор Next.js, файлы в S3 кешируются навсегда | телефон получает картинку под свой экран; оптимизатор работает и для старых фото | 13 |
| API ходит в базу ролью только для данных, миграции — отдельной ролью | ошибка или взлом API не может изменить структуру базы | 8a |
| Сверка S3 с базой в production только отчитывается (`MEDIA_RECONCILE_DRY_RUN=true`) | пока локальная разработка может смотреть в боевой bucket; включить удаление — после проверки отчёта | 11 |
| Контракт API — OpenAPI из кода NestJS, типы `openapi-typescript`, клиент `openapi-fetch`; Swagger UI только в разработке | расхождение API и интерфейсов ловится на сборке, а не у пользователя | 16a–16d |
| Браузерные тесты — Playwright на изолированном стенде с моками 2FA и удаления фона | тесты никогда не трогают базу разработки и боевой S3 | 15 |
| Локальный S3 в разработке и на тестовом стенде — Adobe S3Mock вместо MinIO | MinIO перестала публиковать образы: с сентября 2026 их нельзя скачать ни с Docker Hub, ни с quay.io; production использует облачный S3 и не затронут | 21b |
| Сторонние Docker-образы закреплены по digest, обновления предлагает Dependabot | один и тот же тег со временем может указывать на другой образ; обновление приходит PR и проходит CI | 21b |
| Демо-данные (`pnpm db:seed`) с тестовым паролем в репозитории, только для локальной базы | новый разработчик входит в систему за минуты; в production такие учётные записи не создаются | 21a |
